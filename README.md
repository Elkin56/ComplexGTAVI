# COMPLEX PC: Telegram Mini App «Розыгрыш PS5 + GTA 6»

Готовое к запуску приложение: Mini App для участников, админ-панель для сотрудников, бот, база данных, миграции, тесты, Docker.
Интерфейс на русском, тёмный брендовый стиль (#050705 / #111511 / #A5FF35), логотип COMPLEX PC.

## Как это работает

1. Пользователь открывает бота → **/start** → «Открыть приложение». Принимает правила и согласие на обработку данных.
2. После покупки он **добавляет чек** в приложении (номер, сумма, категория, дата, фото по желанию).
3. Если настроена **сверка с кассой/1С** и сумма совпала, билеты выдаются сразу. Иначе заявку проверяет **сотрудник** в админ-панели: подтверждает (можно исправить сумму и категорию) или отклоняет с причиной.
4. Сервер начисляет билеты **CP-000001, CP-000002…** и шлёт уведомление в Telegram.
5. После закрытия приёма сотрудник вводит **номер шарика, выпавшего на физическом лототроне**, проверяет владельца и фиксирует победителя. Случайного выбора в приложении нет.

**Правила начисления** (не суммируются, берётся максимум): от 5 000 ₽ → 1 билет; покупка ПК → 2; от 30 000 ₽ → 2. ПК на 30 000 ₽+ даёт 2 билета, а не 4.

## Архитектура

```
apps/web            Next.js 16 (App Router), React 19, TypeScript, Tailwind 4
  src/app/            экраны Mini App и админ-панель (/admin)
  src/app/api/        REST API (маршруты Next.js), вебхук бота, cron, экспорт
  src/server/         проверка initData, RBAC, Prisma-адаптер, Telegram, сервисы
  prisma/             схема и SQL-миграции
packages/core       чистая бизнес-логика без зависимостей от БД и фреймворка:
                    правила билетов, заявки, отмена, финал, initData, RBAC, даты, CSV
```

Ключевое: вся логика выдачи билетов живёт в `packages/core` и работает через интерфейс `Store`. Для боевой базы это `PrismaStore` (транзакции PostgreSQL), для тестов `MemoryStore`. Клиентский JavaScript билеты выдать не может: это делает только сервер.

## Быстрый старт (Docker)

```bash
cp .env.example .env        # заполните BOT_TOKEN, WEBHOOK_SECRET, CRON_SECRET, APP_URL, ADMIN_TELEGRAM_IDS
docker compose up --build   # PostgreSQL + миграции + приложение на http://127.0.0.1:3000
```

Миграции применяются автоматически (сервис `migrate`). Проверка: `curl localhost:3000/api/health`.

### Подключение бота

1. В @BotFather: `/newbot` → получите **токен** → `BOT_TOKEN`.
2. Сгенерируйте секреты: `openssl rand -hex 24` для `WEBHOOK_SECRET` и `CRON_SECRET`.
3. Свой Telegram ID (узнать у @userinfobot) → `ADMIN_TELEGRAM_IDS`. Эти люди автоматически получают роль **OWNER**.
4. Опубликуйте приложение по **HTTPS** (см. ниже) и укажите адрес в `APP_URL`.
5. Зарегистрируйте вебхук, кнопку меню и команды: `npm run bot:setup -w @complex/web`.
6. Откройте бота, нажмите **/start**. Владелец заходит в «Профиль» → «Админ-панель» → «Настройки акции»: задаёт даты, часовой пояс, название, ссылку на эфир и нажимает «Запустить акцию».

## Деплой на VPS (рекомендуется)

```bash
# на сервере с Docker, домен уже смотрит на IP сервера
git clone <репозиторий> && cd complex-pc
cp .env.example .env && nano .env     # APP_URL=https://ВАШ_ДОМЕН, DOMAIN=ВАШ_ДОМЕН, POSTGRES_PASSWORD=...
docker compose --profile prod up -d --build
npm i && npm run bot:setup -w @complex/web   # или выполните скрипт на своём компьютере с тем же .env
```

Caddy сам получит HTTPS-сертификат. **Cron для напоминаний** (раз в час):

```
0 * * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ВАШ_ДОМЕН/api/cron/reminders >/dev/null
```

Резервные копии: `docker compose exec db pg_dump -U postgres complex > backup.sql` (по расписанию).
Обновление: `git pull && docker compose --profile prod up -d --build` (миграции применятся сами).

## Деплой на Vercel (альтернатива)

Подойдёт с внешним PostgreSQL (Neon, Supabase, свой). Подробная инструкция: `docs/VERCEL.md`. `apps/web/vercel.json` содержит ежедневный cron (на бесплатном тарифе чаще нельзя). Миграции: `DATABASE_URL=... npm run db:migrate -w @complex/web` с вашего компьютера. Фото чеков хранятся в базе, поэтому диск не нужен. Ограничения: размер запроса до ~4,5 МБ (фото сжимается на устройстве до 1600 px), массовая рассылка по завершении может не уложиться в лимит времени функции. Для больших аудиторий лучше VPS.

## Роли

| Право | STAFF | MANAGER | OWNER |
|---|:-:|:-:|:-:|
| Заявки: подтвердить/отклонить, ручная выдача, участники, статистика | да | да | да |
| Отмена покупок, журнал действий, экспорт CSV/XLSX | | да | да |
| Настройки акции, запуск, закрытие приёма, финал и победитель, сотрудники | | | да |

Права проверяются на сервере в каждом запросе (RBAC), интерфейс только скрывает лишнее.

## Безопасность

- **initData проверяется на сервере** по официальному алгоритму (HMAC-SHA256, срок жизни, защита от подмены). `initDataUnsafe` не используется.
- Секреты только в переменных окружения. Вебхук бота защищён `secret_token`, cron защищён `CRON_SECRET`.
- **Нет двойных начислений:** уникальный индекс на номер чека, транзакции, блокировки строк (`FOR UPDATE`) при решении по заявке, повторный запрос возвращает «уже обработано».
- Номера билетов из последовательности PostgreSQL: повторов нет, возможны пропуски при откате транзакции (для шариков это не мешает).
- Билеты и покупки **не удаляются**: отмена переводит их в `CANCELLED`/`VOID`, всё пишется в журнал (`AuditLog`).
- После закрытия приёма новые билеты выдать нельзя (блокировка на уровне базы), закрыть приём нельзя при необработанных заявках.
- Фото чека: проверка реального формата по сигнатуре, до 4 МБ, доступ только сотрудникам.
- Экспорт: короткая подписанная ссылка (5 минут), ячейки с `= + - @` экранируются от формул Excel.
- Заголовки: CSP `frame-ancestors` только для Telegram, `nosniff`, `no-referrer`. Лимит заявок: 5 в сутки на пользователя.
- Состояния подключения: если приложение открыто не из Telegram, нет базы или не заданы переменные, пользователь видит понятное сообщение, а не пустой экран (`/api/health` для мониторинга).

## Автопроверка чеков по кассе/1С (необязательно)

Задайте `RECEIPT_API_URL` (и `RECEIPT_API_TOKEN`). Приложение будет вызывать:

```
GET {RECEIPT_API_URL}?receipt=<номер>&date=<YYYY-MM-DD>     Authorization: Bearer <токен>
200 {"found": true, "amount": 5400, "category": "PC"}   |   200 {"found": false}   |   404
```

Билеты выдаются автоматически **только при точном совпадении суммы**. Расхождение, отсутствие чека или недоступность кассы отправляют заявку сотруднику с пометкой. Адаптер под вашу кассу пишется в `src/server/verifier.ts`.

## Тесты

```bash
npm test                                   # логика без базы (60 тестов)
docker compose up -d db
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/complex npm test   # + интеграционные на реальной PostgreSQL (30 тестов)
```

Покрыто: расчёт билетов и границы сумм, защита от повторных и параллельных чеков, период и закрытие акции, подтверждение/отказ/отмена, финал и победитель, проверка initData (подделка, срок), права ролей, фото, экспорт, вебхук, уведомления, лимиты.

## Локальная разработка без Telegram

```
DEV_AUTH_BYPASS=true
NEXT_PUBLIC_DEV_USER_ID=7001     # ваш ID из ADMIN_TELEGRAM_IDS
```

`npm run dev -w @complex/web`, открыть http://localhost:3000. В production этот режим отключён принудительно. Для проверки внутри Telegram нужен HTTPS-туннель (например, `cloudflared tunnel --url http://localhost:3000`).

## Что нужно сделать перед запуском

- **Юридически проверить правила и согласие** (`src/lib/rules.ts`): организатор, ИНН, возраст, территория, хранение данных, вручение приза, налоги. Сейчас там черновик с полями в [скобках]. При изменении текста обновите `RULES_VERSION`, и пользователи согласятся заново.
- Подключить кассу/1С, если нужна автопроверка.
- Настроить резервное копирование базы.
- Миграция написана вручную и проверена на PostgreSQL 16. Если меняете схему, создавайте новые миграции командой `npx prisma migrate dev` в `apps/web`.
